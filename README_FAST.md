# 全位置が確率ベクトルの長文を扱う、多層・2階微分可能Replace

## 結果と適用範囲

`soft_pipeline.py` は、各位置が `[256]` の確率ベクトルである入力を、そのまま複数の置換層へ渡せます。
入力文字列の列挙、位置ごとのargmax、学習中のハードな規則選択は行いません。
先の `replace_exact.py` と異なり、**完全な確率分布の押し出しを計算する厳密版ではありません**。
固定の局所窓・相関の省略・期待位置での出力配置を用いる、C²の連続拡張です。

実験では、約1,024バイトの人工文書4件で3層を学習し、未使用の乱数seedから生成した
約1,024 / 4,096 / 16,384バイトの文書で評価しました。文書には複数の置換箇所、
可変長のキャプチャ、置換しない周囲の文章、末尾の未完パターンが含まれます。
入力は全位置・全256成分が厳密に正である密な分布です。

取得した3規則:

```
<*>  -> [capture0]
[*]  -> {capture0}
{*}  -> !capture0capture0?
```

つまり `hello <ABC>` は3層を経て `hello !ABCABC?` になります。
2層目以降は、前の層が出力した未確定の確率ベクトルを直接入力とします。

**実験の制約を省略しないでください。**
- キャプチャ長は1～3バイト。長い「文書」で試しましたが、長い「一回のキャプチャ」ではありません。
- 規則の構造候補と、左辺の区切り文字の強い初期事前情報（該当文字のlogit=10、他は0）を与えました。
- 右辺のリテラル文字は256候補の一様logitsから学習。左辺・右辺のリテラル分布も学習対象です。
- 構造を選ぶlogits、通常文字のlogits、通常文字とキャプチャの配置候補を学習しますが、
  任意の長さの任意の規則をゼロから探索する実装ではありません。
- 各層80更新のカリキュラムでは、中間段階の正解も与えました。その後40更新は3層の最終出力だけで学習。
- 単一seedの小規模人工課題であり、一般のプログラム合成や自然言語タスクの実証ではありません。

## 実行

CPU、Python 3.10以上、PyTorch、Cコンパイラ `cc` が必要です。
Linuxで実行確認。ネイティブ走査は初回に同梱 `scan_cpu.c` を一時ディレクトリへコンパイルします。
CUDA・Windows・macOS対応は今回未検証です（共有ライブラリのビルド指定はLinux向け）。

```bash
python -m pip install -r requirements.txt
python test_soft_pipeline.py
python train_soft_long.py --length 1024 --warmup 80 --joint 40 --learn-bytes \
  --output soft_parametric_long_results.json
python evaluate_checkpoint.py soft_parametric_long_results.json --length 4096 --noise .1
python benchmark_soft.py
```

最終版と学習済み状態:
- `soft_parametric_long_results.json`: 全設定・評価数値・抽出規則
- `soft_parametric_long_results.pt`: 重み（隣のJSONと組で復元）
- `soft_parametric_long_training.jsonl`: 学習ログ
- `learned_pipeline.json`: 整数推論用の規則列

確率やPyTorchを使わず実行するには:

```bash
python -S run_rule_pipeline.py learned_pipeline.json --input input.txt --output output.txt
```

## 何を近似したか

1. 入力上の局所的な区切り一致を確率として計算します。重なった一致イベント間の相関は省きます。
2. 範囲内で最初の区切りが見つかる重みは `q_j * product(k<j, 1-q_k)`。
3. 左から非重複に消費する到達重みは有向非巡回グラフの再帰で計算します。
4. キャプチャ内の文字は、その位置の周辺分布をコピーします。一致条件による厳密な条件付き分布ではありません。
5. 各位置から出る期待文字数を累積して出力位置を決め、quintic補間で隣接セルへ配置します。
6. 分布を正規化して次の層へ渡します。出力文字間の相関と出力位置の完全な分布は保持しません。
7. 出力の連続長を次層の存在ゲートへ変換するので、長さ分布もモーメント近似です。

出力正規化は、各セルの総質量mと文字別質量vについて

    Y = (v + eps*(1-m)^2 * uniform) / (m + eps*(1-m)^2), eps=1e-4

とします。m>=0で分母は正、m=1なら補正は0、m=0なら一様パディングです。
整数位置ではquintic補間が厳密な配置になります。

加えて既定 `match_power=2` は、区切り判定だけに `p^2/sum(p^2)` を使います。
学習可能な区切り文字のlogitsにも同じ鋭さを適用します。コピーする文字分布自体を
無条件にOne-Hotへ変える処理ではありませんが、これは明確に確率の解釈を変える操作です。
厳密なBayes推論や元の期待値だとは主張しません。

`match_power=1` でこの操作を外せます。比較用の初期実験では、入力不確定度0.1の
位置別正解率は約1.9%でした（`soft_long_baseline_results.json`）。長文ではわずかな
期待長の誤差が累積するため、このモデルは区切りの確信度に強く依存します。

## 2階微分と速度

走査は

    r[i] = source[i] + sum_d edge[i-d,d] * r[i-d]

です。前向き・転置の解法をCで実装し、逆伝播は陰関数の随伴式

    grad_edge[i,d] = r[i] * adjoint[i+d]

で計算します。逆伝播の中でも同じ微分可能な走査を呼ぶため、2階微分を保持します。
`detach`した勾配、STE、サンプルによる近似勾配は使いません。

全位置の全256入力成分、連続長、規則logits、学習する文字logitsについて
`gradcheck` / `gradgradcheck` を実行しました。Cの前向き走査・転置走査の両方も検証済みです。

入力長L、局所イベント数E、最大消費長D、一イベントの出力長o_eとすると、
走査はO(LD)、主な転送はO(256*L*sum_e o_e)。固定した小さな窓・構造集合ならLに線形です。
一方、イベント数はキャプチャ上限やキャプチャ数で増えます。大きい窓が無料になるわけではありません。
長さを増やす層を多数重ねると、保守的な出力容量も増えるため、任意深さで小メモリとは言えません。

## APIと現在の制限

```python
from soft_pipeline import Rule, SoftReplaceLayer, SoftReplacePipeline

layer = SoftReplaceLayer(
    [Rule((60,-1,62),(91,-1,93)), Rule((60,-1,62),(-1,-1))],
    min_capture=1, max_capture=3,
    trainable_literals=True,  # リテラル文字を256候補で学習
    pattern_prior=10.0,      # 初期の区切り文字の強いヒント
    match_power=2,
)
# X: [batch, capacity, 256] の正規化された確率ベクトル
# length: [batch] の連続長座標
Y, output_length = layer(X, length)
model = SoftReplacePipeline([layer, another_layer])
Y, output_length = model(X, length)
```

- 1層に対して複数の構造候補を渡し、1規則を選ぶ分布を学習します。複数層で複数規則を順に適用します。
- `trainable_literals=True` は各候補のリテラルを全256チャネルの分布として学習します。
  キャプチャの配置・個数は構造候補で与えます。同じ候補内で同じ元バイトを使う箇所はパラメータ共有です。
- 左辺の先頭・末尾はリテラルが必要。先頭/末尾ワイルドカード、連続ワイルドカードはこの高速版では拒否。
- 最大3キャプチャ、最大512局所イベント、右辺最大64命令。
- キャプチャ範囲外の一致は探索対象外。学習・一致保証は宣言された範囲内に限ります。
- スカラ長のquintic存在ゲートは整数点で1階・2階微分が0。この制約は残っています。
- 自由な256+nベクトルから任意の規則構造まで全て学習する高速エンジンではありません。
  小問題の任意の支持集合を扱う厳密なAPIは、引き続き `replace_exact.py` にあります。
- 支持範囲内のOne-Hot入力・確定規則では修正版の離散置換と一致。複製、削除、2キャプチャ並べ替えもテスト。
- 出力には `max_output` に相当する離散版の上限復帰処理はありません。保守的な容量を確保し、
  小さすぎる明示容量は例外にします。メモリを超えるケースは別途制限が必要です。

## 正則化と学習方法

正規化エントロピーを、規則選択と各文字分布へ適用します。係数0.02をカリキュラム後半から導入。
有限logits上では滑らかですが、誤った規則を早期に確定させる可能性があるため、初めは0です。

学習損失は `mean token CE + 1000 * ((predicted_length-target_length)/target_length)^2`。
CEには1e-12を足してlogを取り、ハードなclampを避けています。
この強い長さ重みは今回の位置ずれを抑える課題向けであり、普遍的な最適設定ではありません。
中間段階の教師を使わない学習、未知の構造を増やす学習、弱い初期区切り情報での安定性は未解決です。

本実装の成果は「長文の全位置を確率ベクトルのまま扱い、多層で勾配を通し、
制約された規則族で実際に学習・離散化できた」ことです。元の全仕様に対する厳密かつ高速な
一般解が完成したという意味ではありません。
