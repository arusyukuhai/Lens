# Lens / Replacer — 200世代付近での停止・メモリ肥大対策

## 変更点（HOF=4096は維持）

- `--hof-size` のデフォルト4096は変更していません。世代ごとにHOF全体（各1500ルール）を再ハッシュする処理をやめ、追加・脱落時のみ集合を更新します。
- HOF挿入時、ベストモデル保持時、エリート引継ぎ時の`copy.deepcopy`を除去し、既存のRuleを共有するスナップショットにしました。変異は従来どおり新しいRuleを生成するため、個体の独立性を保ちます。
- HOF個体の次世代注入で行っていた入れ子の全個体ハッシュ計算を、事前構築した署名集合による判定へ変更しました。HOF選出時も乱数発生器を統一しました。
- checkpoint保存時に各ゲノムを巨大なネスト辞書に展開しなくなりました。pickleの参照共有を使い、保存時の瞬間的なメモリ倍増を軽減します。既存v4の辞書型チェックポイントもロードできます。旧形式ロード時には重複ルールもインターンして共有し直します。
- 回転した学習ケースでは、旧世代のスコアキャッシュを次世代の評価開始前に解放します。
- ネイティブCPU評価器は、極端に膨張する候補に対して**学習時の資源予算を超えたサンプルのみ得点0**として先へ進めます。置換ルールや文章を切り詰めることはありません。`budgetHits=`が表示された場合、該当世代で予算に当たったサンプルがあります。

## 導入

修正した3ファイル `main.py`、`replacer_native.cpp`、`native_cpu.py`を必ず**同じディレクトリ**に配置し、従来どおり`python3 main.py ...`で起動してください。ネイティブCPUの共有ライブラリはコードのハッシュが変わるため自動再コンパイルされます（C++コンパイラが必要）。

```
python3 main.py --backend cpu --load lens_ar_checkpoint.pkl --hof-size 4096 [従来の引数]
```

※ `[]`内は説明用プレースホルダーです。入力コーパス等の引数は以前と同じものを指定してください。

追加の `--max-state-bytes` は既定で65536。例: `--max-state-bytes 262144` でより大きな内部状態を許可できます。`0`なら**長さ制限のみ解除**しますが、暴走によるハングを防ぐ計算量上のガードは残ります。

注：今回の防御は通常のモデル・置換ルールそのものに長さ制限を設けるものではなく、評価が病的に膨張した候補にペナルティを与えます。限界を越えた候補を得点0とする分、以前の完全無制限評価と比べて選択基準は変わりえます。

## 検証内容

- 主要テスト 39件 + サブテスト 6件通過、標準self-test通過
- `--hof-size=4096` のまま、サンプルデータで225世代まで継続完走
- 225世代の新形式checkpointから230世代まで再開完走
- 異常に指数増殖するルールを同じCPUバッチに混ぜても異常終了せず、他個体を引き続き評価することを確認
- 新形式checkpointでのルール共有と、従来v4の辞書checkpoint読込を検証

**限界**：大規模な実学習（実コーパス×450個体×1500ルール×4096HOF）を数百世代実行する検証は、この環境では行っていません。したがって実負荷での完全な無停止・メモリ使用量を保証するものではありません。実環境でのログに`budgetHits=`が増えた場合は、学習コストの上限を踏まえたチューニングが必要です。
