# v57：HoF評価上限・停滞検出・探索多様性の修正

## 再開

このZIPには添付された2360世代のチェックポイント（450個体×1500規則、HoF 1024体）、履歴、既存モデルも含みます。学習コーパス `github-code.txt` は元の実行環境にあるものを同じフォルダに置いてください。Macでは既存のPyTorch環境をそのまま使用します。

```bash
python3 main.py --backend mps \
  --load minimal_gp_checkpoint.npz \
  --checkpoint minimal_gp_checkpoint_v57.npz \
  --save best_minimal_gp_v57.json \
  --history-csv fitness_history_v57.csv \
  --plot-prefix training_v57
```

次回から `--load minimal_gp_checkpoint_v57.npz` で再開。`--generations` は追加世代数ではなく終了世代番号です。入力のチェックポイント・既存CSV・既存モデルを残す出力名にしています。

`latest_minimal_gp.json` は最新の評価済みチャンピオンで、チェックポイント保存時と正常終了時に保存します。`best_minimal_gp_v57.json` は読み込んだ過去最高の観測値を更新した場合のみ作成します。違う評価ケース間の過去最高値は汎化性能の証明にはなりません。

## 確認された問題

- 元の `hof_genomes = [e.genome for e in hof_archive]` は全件評価。HoF 1024体なら、人口450体と合わせて最大1474体が対象でした。
- 添付チェックポイント履歴の直近200世代は、平均最高相関0.995471、集団平均0.985485。直近500世代のうち先頭200世代は、それぞれ0.995531、0.985599でした。この区間では改善が見られません。
- それでも短期停滞カウンタは直近200世代で最大3、前の比較区間で最大4。微小な改善でゼロに戻るためです。履歴最後の旧カウンタは0、新方式を同じ履歴に適用した長期カウンタは36でした。
- CSVには再起動・再開による世代番号の重複があります。上の集計にはチェックポイントに保存された一連の2360世代を使っています。

## 変更

| 項目 | v57 |
|---|---|
| HoF評価 | 毎世代、全アーカイブから一様ランダム・重複なしで最大32体。`--hof-eval` で変更 |
| HoF保存数 | 再開時に1024体を保持。評価数とは独立 |
| 評価キャッシュ | ケース識別子の組全体が一致する場合のみ再利用。非ローテーション世代でも古いHoFスコアを流用しない |
| HoF履歴 | 実際に評価したエントリだけ更新。未評価ケースに古い点数を記録しない |
| 近縁HoF置換 | 両者に共通する評価ケースの得点差で比較。比較材料がないときは置換しない |
| HoF親・注入 | 現在のケースで評価済みの個体を使用。エリートと同じ構造の注入は除外 |
| 長期停滞 | 隣接する100世代平均を比較。平均相関の改善が0.0002以下なら探索圧を上げる。履歴から起動時に復元 |
| 親選択 | トーナメントサイズ20→6。25%の親選択をケース別MAD epsilon-lexicaseにして専門個体も残す |
| 停滞時探索 | 既存の局所／中規模／広域変異配分を長期停滞に連動。移民率は通常1%、最大5% |
| Ridge | 学習行列上のゼロ列を除外して同じ式を計算。推論側もゼロ重み列を除外 |
| 相関 | 平均順位の同順位処理をNumPy化 |
| 出力 | グラフ毎世代→25世代ごと。CSVに余分な既存列があるだけなら全履歴を書き直さない |
| 最新モデル | 過去最高更新とは別に保存し、比較可能にする |

32体制限により、最大対象数は1474→482（約67%減）。これは重複除去・再利用前の件数であり、実測速度倍率ではありません。全アーカイブの構造をGPU規則プールの生存集合に含め、GC後に古いプール参照を使わないようにしています。

長期平均には評価ケースの難度変動も残るため、停滞カウンタは探索制御の指標であり厳密な収束判定ではありません。専門個体選択や移民率変更による精度改善は、長期再学習で確認する必要があります。既存Metalカーネル・目的変数・学習内ホールドアウト分割・ridge正則化は変更していません。

調整用オプション：

```text
--hof-eval 32
--plateau-window 100
--plateau-min-gain 0.0002
--plateau-immigrants 0.04
--specialist-rate 0.25
--tournament 6
--plot-every 25
```

より多様なコードへの評価を重視する追加実験なら `--cases 6 --samples 36` でケース数を増やせますが、評価入力が倍になるため既定値は3×36のままです。

## 汎化性能の比較

`audit_generalization.py` は保存済みモデルの重みを固定し、同じ未知のコード・同じノイズ列で比較します。監査用データでは回帰の再学習をしません。学習に使わなかった別のコーパスを `validation-code.txt` として用意してください。

```bash
python3 audit_generalization.py --backend mps \
  --models best_minimal_gp.json latest_minimal_gp.json \
  --local-corpus validation-code.txt --cases 32 --samples 36 \
  --output audit_v57.json
```

出力は各ケースの相関、平均相関、2番目−1番目の平均差、ケース単位のペア・ブートストラップ95%区間。学習中の相関とは評価方法が違うため、絶対値を直接比較しないでください。監査データを繰り返し見て選別すると独立性が失われます。
